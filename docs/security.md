# Security requirements

These rules are mandatory for all code in this repository. Threats they address: [threat-model.md](threat-model.md).

## Funds and keys

- No private keys, seeds or xprv on servers — only addresses and xpubs ([ADR-0002](adr/0002-watch-only.md)).
- Receiving addresses are pinned in config with a checksum, verified at start-up and on every cycle; on mismatch the
  gateway alerts and stops issuing invoices. There is no API, bot command or admin UI to change addresses.
- The verifier compares the recipient against the pinned list, not against a mutable table.

## Verification

- Only final and successful transactions are credited (TRON: solidified and `SUCCESS`; TON: masterchain, no bounce,
  not aborted).
- The asset is identified by the contract / master address from config, **never** by symbol, name or metadata.
- The indexer supplies candidates; a finalized-state query is the source of truth; a second provider is optional.
- Idempotency: `UNIQUE(network, tx_hash, log_index | lt)`.
- Scan cursors advance only after a durable write, overlap the previous window and catch up after downtime instead
  of jumping ahead.

## Transport and external calls

- TLS only to providers. Timeouts, response size limits and schema validation (zod) for every response.
- No telemetry, update checks, remote config or calls to author-operated servers. Every external host is an explicit
  config parameter and is documented.
- Webhook SSRF protection is configurable (private addresses can be allowed explicitly).

## Access and secrets

- No "first visitor" setup pages. Initial secrets are generated by a local CLI command or provided via environment.
- Randomness for secrets, memos and tokens comes from `node:crypto` only.
- Secrets are compared with `crypto.timingSafeEqual`.
- API keys are stored hashed, with scopes and rotation.
- An ops / admin interface, if any, is never exposed publicly; rate-limited, with 2FA.
- Secrets come from environment variables or 0600 files, are redacted in logs and never appear in API responses.
- The webhook secret is separate from the API key and is never transmitted.

## Data and logs

- Every verifier and settlement decision is written to an audit log with its reason.
- Personal data is minimised; client IP addresses are not stored by default.
- Documentation states explicitly that AML screening sends addresses and transactions to the vendor.

## Supply chain

- Minimal dependencies; each one is justified in its pull request ([ADR-0007](adr/0007-minimal-dependencies.md)).
- Exact versions, committed lockfile, `npm ci --ignore-scripts`, Dependabot with manual review, `npm audit` in CI.
- License allowlist checked in CI ([ADR-0006](adr/0006-apache-2-clean-room.md), [ADR-0023](adr/0023-mpl-for-dev-dependencies.md)).
- No `latest` tags: images pinned by version and digest; GitHub Actions pinned by commit SHA.
- Planned for releases: signed artifacts and images, SBOM, provenance attestations.
